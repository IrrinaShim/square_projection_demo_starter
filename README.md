# Наблюдаемая сетка КА

Локальное приложение для Linux/Python 3.12 одновременно показывает гномоническую проекцию наземного наблюдателя, конфигурацию `(y,z)` в ОСО и локальный 3D-вид относительных траекторий. Общий ползунок синхронизирует три картины **одного выбранного пролёта**. В режиме J₂ число КА на стороне `N` меняется от 2 до 10, всего `N²` (4–100) КА. КА 0 — опорный; при `N=2` сохранён обход **0–1–2–3–0**. Графиков тяги и `Δv` в окне нет.

## Запуск

Из корня проекта, в уже подготовленном окружении:

```bash
.venv/bin/python main.py
```

Для нового окружения при переносе проекта (в текущей рабочей папке это **не требуется**):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

На системе без дисплея проверка окна:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python tests/smoke_ui.py
```

Проверка расчётов:

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v
```

Проверено в подготовленном `.venv`: 7 математических тестов прошли; offscreen-проверка загрузила HCW, независимый J₂ для `N=2,3,10` и исторический CSV, проверила обе 2D-картины, индикаторы, таблицы параметров, экспорт элементов, ползунок, анимацию и оба 3D-вида. Зависимости повторно не устанавливались.

## Управление

- «Свободный пролёт HCW»: измените угловую сторону (1–20°), высоту, наклонение, широту или долготу и нажмите «Пересчитать». Выберите один из трёх вариантов: подобранный свободный (открывается первым), пробный свободный или идеализированно удерживаемый квадрат ОСО. Таблица сравнивает их на одной временной сетке. Интервал и параметры МНК меняются в `scenarios/free_zenith.json`, затем нажмите «Перезагрузить JSON».
- «Независимые орбиты J₂»: выберите `N=2…10`; кнопка «Оскулирующие элементы» раскрывает элементы **всех `N²` КА**, а «Сохранить элементы JSON» экспортирует их с индексной матрицей и общей эпохой. Исходные четыре угла заданы в `scenarios/independent_j2_4sat.json`, внутренние начальные состояния получаются детерминированно и далее интегрируются отдельно. Высота, наклонение и угловая сторона меняются через JSON вместе с угловыми элементами. Ползунок показывает один пролёт; аудит всех пар на полном витке при `N>2` идёт в фоне. Пока он не закончен, индикатор показывает «проверка выполняется».
- «Историческая управляемая траектория»: считывает согласованные `config.json`, `trajectories.csv` и `controls.csv` из `legacy/example_controlled/`. Пространственная сторона 20 км задана старыми данными, поэтому ползунок угловой стороны не действует. Высота и наклонение также фиксированы данными; широту и долготу для реконструкции наблюдения можно изменить.
- Ползунок времени, «Пуск/Пауза», «В начало» и скорость анимации управляют всеми панелями. При запуске открыт локальный 3D-вид ОСО без Земли, с одинаковым масштабом осей и фрагментами относительных траекторий. Общий инерциальный вид доступен переключателем.
- Над графиками указаны модель, высота, наклонение, период опорной орбиты, координаты наблюдателя, заданная сторона и рабочее окно. Кнопка «Начальные дальности, положения и скорости» раскрывает таблицу трёх ведомых КА. Для исторических CSV дальность не выбиралась, поэтому в её столбце стоит «—».
- Зелёная полоса под ползунком показывает узлы, где выполнены критерии формы и видимости **всей сетки**. Для `N>2` учитываются все внутренние точки и ячейки, порядок строк и столбцов, угол места каждого КА и истинный угловой шаг соседей. При отказе показаны причины и фактические ошибки; нулевая длительность означает отсутствие допустимого интервала вокруг эпохи. Отклонение среднего размера от `tan(θ)` показано отдельно. Индикатор расстояний сообщает горизонт проверки: для J₂ — полный номинальный виток, для HCW — показываемое окно. Пробный HCW-вариант прямо помечен как неподтверждённый по безопасности.

Гномонические `ξ, η` безразмерны. На осях изображения подписаны **координатные углы** `atan(ξ)` и `atan(η)` в градусах; они не равны истинному угловому расстоянию каждой пары соседних КА. Координаты yOz и расстояния даны в км, время — в с. `εb` и `εd` безразмерны, `εγ` на экране показано в градусах (в данных — радианы). Показатели сторон и диагоналей в интерфейсе относятся к безразмерной картинной плоскости.

## Структура

- `square_demo/core.py` — общая геометрия ОСО и проекции, HCW и матрицы `P,V`, метрики квадрата и проверяемый `TrajectoryResult` по `docs/TRAJECTORY_CONTRACT.md`.
- `square_demo/orbit_j2.py` — оскулирующие элементы, отдельное интегрирование до 100 абсолютных орбит с J₂ и блочная проверка всех пар на полном витке.
- `square_demo/grid.py` — постоянная индексация, построение начальных состояний внутренних КА и показатели всех точек, соседей и ячеек сетки.
- `square_demo/providers.py` — три прежних HCW-варианта, новый `independent_j2` и `legacy_replay`; сценарии читаются из JSON и проверяются. Все возвращают один тип `TrajectoryResult`.
- `square_demo/ui.py` — PySide6 и Matplotlib; рисует уже рассчитанные данные, не вычисляя орбитальную динамику. Новый провайдер подключается к словарю `PROVIDERS` и возвращает тот же контракт.
- `tests/` — проверки вычислений и короткая offscreen-проверка окна.

## Модель и ограничения

Основной источник формул нового режима — `docs/inverse_projection_4sat_draft.tex`. Опорный КА движется по круговой двухтельной орбите. Зенит назначен при `t=0`. Для стороны `θ` используется `α=tan(θ)` и точки `(0,0), (α,0), (α,α), (0,α)`.

**Как выбираются начальные условия:** пробный вариант из `initial_family` сценария задаёт каждому ведомому `x_i(0)=0`, `v_rel,i(0)=0`, `y_i(0)=D₀ ξ_i`, `z_i(0)=D₀ η_i`; при зените `D₀=630 км`, поэтому `λ_i=D₀=630 км`. Это демонстрационный пробный выбор, **не оптимизированная орбита**. Для подобранного варианта начальная точка лежит на том же точном луче изображения: `ρ_i(0)=h_i+λ_i g_i`. Четыре свободных параметра каждого ведомого — `λ_i` и три компоненты `v_rel,i(0)` — определяются регуляризованным МНК для системы `H_i(t)[P(t)ρ_i(0)+V(t)v_i(0)]=b_i(t)`. По умолчанию используются 21 узел в пределах ±150 с и коэффициент регуляризации 1 с безразмерной нормировкой неизвестных; значения редактируются в JSON. Это окно подбора находится внутри показываемого окна −450…450 с. Начальная проекция в зените остаётся **точной** при любом найденном `λ_i`. Остальные узлы проверяются повторным вычислением фактической гномонической проекции и всех критериев. Оба свободных варианта распространяются HCW с `c=1` без тяги; формирование найденных начальных состояний не моделируется.

Третий вариант — пространственный квадрат, идеально удерживаемый в ОСО. Он служит **геометрическим ориентиром** и включает идеализированное непрерывное ускорение, необходимое для постоянных координат ОСО в HCW. Его нельзя считать свободным движением или реализованным проектом управления. В историческом режиме начальные относительные положения и скорости читаются из CSV при `t=0`; никакая дальность `λ_i` там не выбирается. На каждом отсчёте всех вариантов заново вычисляются абсолютные положения, положение вращающегося с Землёй наблюдателя и видимая проекция. Таблица показывает длительность связного допустимого интервала вокруг зенита по порогам `visibility` из JSON и максимальные `εb`, `εd`, `εγ` за **всё показываемое окно**, а также минимум угла места и расстояния между КА. Если подбор не увеличит длительность при других параметрах, окно прямо сообщает об этом.

Для исходного `scenarios/free_zenith.json` (θ=1,8183029644518331°, сетка −450…450 с с шагом 5 с) получено:

| Вариант | Допустимый интервал вокруг зенита, с | Длительность, с | max εb | max εd | max εγ, ° | min угол места, ° | min расстояние, км |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Удерживаемый ОСО | −60…60 | 120 | 0,4147 | 0,0925 | 7,88 | −3,52 | 20,00 |
| Пробный свободный | −60…60 | 120 | 0,3829 | 0,0995 | 7,81 | −3,52 | 17,69 |
| Подобранный свободный | −215…210 | 425 | 0,2443 | 0,0833 | 5,62 | −3,91 | 17,45 |

Длительность считается по связной группе узлов, содержащей зенит; экстремумы ошибок, угла места и расстояния относятся ко всем 181 узлам. Отрицательный минимум угла места означает, что края всего окна невидимы. Улучшение здесь относится к выбранному сценарию и допускам, а не доказывает физическую пригодность найденных начальных скоростей.
Для подобранного варианта модули трёх начальных относительных скоростей составляют примерно 42,1, 46,8 и 4,7 м/с. Затраты на создание такой начальной конфигурации здесь не рассчитаны.

При 630 км `θ=atan(20/630)=1.8183029644518331°` соответствует поперечной стороне 20 км. Значение 20° принимается для визуализации, но линейная HCW-динамика на таком масштабе **не валидирована**. Окно показывает `max ||ρ||/a₀`. HCW-варианты не моделируют J₂, атмосферу, ошибки наведения и точную динамику ведомых; их шесть пар проверяются только в показываемом интервале. Порог из `illustrative_min_separation_km` — настраиваемый иллюстративный ориентир, не доказанная безопасная дистанция.

## Исходный случай N=2: четыре независимые орбиты с J₂

При `N=2` [исходные элементы и параметры](docs/Исходные%20данные.md) задают четыре КА на одной эпохе **2026-09-28T00:00:00Z**. Их начальные инерциальные состояния получены из подобранного HCW-кандидата, но далее каждый КА интегрируется отдельно в нелинейном поле Земли с J₂ без тяги. [Основные положения](docs/Основные%20положения.md) фиксируют модель, системы координат и критерии. Положение наблюдателя восстанавливается на вращающейся сферической Земле с условным нулевым углом Гринвича на эпохе; это не точная эфемеридная привязка к данной UTC-дате.

В показываемом окне **−450…+450 с** начальная проекция точна до `6,4·10⁻¹⁵` в гномонических координатах. По принятым критериям видимый квадрат допустим в **86 из 181 узла**; связный интервал вокруг эпохи **−215…+210 с**, длительность **425 с**. Максимумы ошибок на всём окне: `εb=0,24436`, `εd=0,08285`, `εγ=5,581°`; минимальный угол места `−3,914°`. Края окна поэтому неприемлемы.

Дополнительная проверка охватывает **0…5829,766 с**, один номинальный период опорной начальной орбиты, включая широты до `|82,19°|`. Для каждой из шести пар минимумы уточняются между узлами через условие `(rᵢ−rⱼ)·(vᵢ−vⱼ)=0` с повторным интегрированием J₂. Время от эпохи, место под серединой пары и расстояние:

| Пара | t, с | Расстояние, км | Широта, ° | Долгота, ° |
| --- | ---: | ---: | ---: | ---: |
| 0–1 | 2,290 | 19,995048 | 25,52 | 51,47 |
| 0–2 | 3,109 | 28,276992 | 25,56 | 51,36 |
| 0–3 | 1260,342 | **9,704325** | **74,55** | −100,21 |
| 1–2 | 1280,324 | **10,194464** | **72,87** | −103,62 |
| 1–3 | 5818,014 | 27,309319 | 24,77 | 27,27 |
| 2–3 | 2,053 | 19,995558 | 25,48 | 51,29 |

По иллюстративному порогу **1 км** опасных локальных минимумов на этом витке нет. Этот результат относится только к указанному J₂-кандидату и горизонту. Он не делает безопасным пробный HCW-квадрат: его независимая двухтельная проверка обнаружила сближение двух пар примерно до 0,096 км около четверти витка. У нового кандидата не проверены следующие витки, неопределённость начальных условий, ошибки наведения, атмосфера и более высокие гармоники. Формирование начальной конфигурации и его Δv не рассчитаны.

Машиночитаемый [протокол J₂](docs/j2_pass_results.json) содержит все элементы, метрики, уточнённые события и проверку сходимости. Повтор расчёта:

```bash
.venv/bin/python scripts/check_j2_scenario.py > docs/j2_pass_results.json
```

При уменьшении шагов интегрирования с 2 до 1 с, сетки аудита с 5 до 2,5 с и уточнения с 0,1 до 0,05 с расхождение конечных положений оказалось меньше `2,2·10⁻⁸ км`, парных минимумов — меньше `1,3·10⁻¹⁰ км`. Максимальный относительный дрейф удельной энергии J₂ составил `1,15·10⁻¹⁴`. Это численная сходимость принятой модели, а не оценка физической неопределённости.

## Сетки N=2, 3 и 10

Индексы закреплены по строкам снизу вверх, внутри соседних строк направление счёта меняется; при `N=2` матрица `[[0,1],[3,2]]` оставляет прежний порядок углов. Внутренние КА получают собственные начальные положения, скорости и элементы на общей эпохе. Интерполируются **только начальные данные**; после эпохи каждая орбита интегрируется отдельно в J₂. Проекция строится для всех точек, строки и столбцы показаны линиями, а при `N=10` подписи оставлены лишь у четырёх углов.

На одном окне −450…+450 с при исходной стороне 1,818303° и минимальном истинном угловом шаге 0,1° получено:

| N | КА | Все пары | Допустимый интервал всей сетки, с | Длительность, с | Ближайшая пара на полном витке; расстояние, км |
| ---: | ---: | ---: | --- | ---: | --- |
| 2 | 4 | 6 | −215…+210 | 425 | 0–3; 9,704325 |
| 3 | 9 | 36 | −95…+90 | 185 | 5–6; 4,834755 |
| 10 | 100 | 4950 | −30…+25 | 55 | 80–99; 1,071374 |

Ближайшие сближения для `N=3` и `N=10` приходятся на высокие широты около **74,5° с. ш.** вне показываемого окна. При пороге истинного шага **1°** остаётся лишь 205 с для `N=2`; у `N=3` и `N=10` нет допустимого узла. При **2°** нет допустимого узла ни у одного из трёх примеров. Таким образом, внешний квадрат сам по себе не определяет качество всей сетки. При `N=10` найденный минимум всего на 0,071374 км выше иллюстративного порога 1 км; долгосрочная и эксплуатационная безопасность не установлена.

Для 100 КА полный аудит обрабатывает 4950 пар блоками, уточняет внутренние минимумы по положениям и скоростям соседних узлов и повторно интегрирует в J₂ события возле порога. В исходном примере так проверены 37 близких к порогу минимумов. Пока аудит идёт в фоне, окно сообщает, что вывод о полном витке ещё не готов. Сетка расчёта не грубее 5 с; два экстремума внутри одного шага без смены знака относительной скорости могут остаться невыявленными. Следующие витки, неопределённость начальных состояний и манёвры формирования не моделируются.

Полные элементы всех КА, индексные матрицы и показатели находятся в [N=2](docs/grid_checks/grid_n2.json), [N=3](docs/grid_checks/grid_n3.json) и [N=10](docs/grid_checks/grid_n10.json); [CSV для N=10](docs/grid_checks/grid_n10_pair_minima.csv) содержит минимумы всех 4950 пар с временем и местом. Повторить расчёт:

```bash
.venv/bin/python scripts/check_grid.py
```

Исторический режим переводит метры в километры и переставляет одновременно состояния и управления из старого порядка `[0,1,2,3]` в `[0,1,3,2]`. `f1,f2,f3` — фактически приложенные ускорения в м/с² на 240 полуинтервалах; `Δv` интегрируется по их длительности. Начальные `Δv=0` относятся к показываемому участку. Старые CSV не содержат наблюдателя и инерциальной ориентации орбиты. Для изображения **условно назначен зенит при `t=600 с`** по `scenarios/legacy_replay.json`; полученная видимость не является опубликованным интервалом наблюдения. Пунктирная цель рассчитана из идеального квадрата 20 км в ОСО при этом зените. Старый `shape_metrics.csv` не используется. Исторические состояния остаются результатом прежней управляемой модели, тогда как опорная орбита для реконструкции изображения взята круговой двухтельной: это приближение следует учитывать при научном сравнении.

В 3D полная линия витка относится **только к номинальной орбите опорного КА**. Линии ведомых показывают пройденную часть имеющихся данных. `legacy/reference/` служит справкой и не нужен для запуска.

Числа прежней проверки хранятся в [JSON](docs/two_body_check.json), рисунок — в [PDF](docs/two_body_distances.pdf).

Пересчёт без дополнительных библиотек и сборка отчёта:

```bash
.venv/bin/python scripts/two_body_check.py > docs/two_body_check.json
.venv/bin/python scripts/make_two_body_figure.py
.venv/bin/python scripts/check_j2_scenario.py > docs/j2_pass_results.json
.venv/bin/python scripts/check_grid.py
cd docs
xelatex -interaction=nonstopmode -halt-on-error inverse_projection_4sat_draft.tex
xelatex -interaction=nonstopmode -halt-on-error inverse_projection_4sat_draft.tex
```

Прежняя двухтельная проверка пробного состояния — отдельный скрипт. В GUI свободные HCW-варианты остаются аналитическими, новый J₂-вариант использует независимые абсолютные орбиты, а исторический режим воспроизводит готовые CSV.
