# Исследование пассивных наблюдаемых сеток

Это отдельный расчёт внутри проекта. Существующее графическое окно загружает выбранные наборы орбит из `results/solutions.json` **только при точном совпадении N и целевой внешней стороны** и повторно рассчитывает один пролёт. При старте N=10, 20° сообщает об отсутствии набора: сохранённый N=10 относится к 10°. Результат не является проектом развёртывания группировки. Все аппараты после общей эпохи движутся **без тяги** как отдельные тела в одном стационарном центральном поле Земли с J₂.

## Повторение

Из корня репозитория, в подготовленном `.venv`:

```bash
.venv/bin/python -m orbit_study.run
.venv/bin/python -m orbit_study.check_minima
.venv/bin/python -m orbit_study.check_polar
.venv/bin/python -m unittest tests/test_orbit_study.py -v
```

Отдельный расчёт выбранного случая без окна, с собственными файлами и графиками:

```bash
.venv/bin/python -m orbit_study.analyze --n 5 --threshold-deg 2 --horizon-days 0.2 --output-dir orbit_study/user_runs
```

В окне тот же расчёт запускается только кнопкой «Рассчитать и сохранить графики». Для каждого запуска создаётся отдельная папка с `case.json`, `passes.csv`, `pair_minima.csv` и тремя PNG. Долгосрочные графики не появляются на панели одного пролёта. `solutions.json` содержит `model_version`, хеш исходников численных определений и хеш собственных данных; приложение дополнительно сверяет эпоху, наблюдателя, константы и допуски с текущим сценарием. При несовместимости загрузка останавливается.

Настройки находятся в [search.json](search.json). `--quick` задаёт по 0,25 суток для отладки, `--full` снимает бюджетное ограничение и проверяет все N на 30 сутках. `--sizes 2 3` запускает только указанные размеры и перезаписывает сохранённые результаты; `--resume --sizes 2 3` сохраняет уже рассчитанные остальные N. Для восстановления полного набора после запуска без `--resume` повторите команду без `--sizes`. Не следует использовать быстрый режим как подтверждение долгосрочной повторяемости. Установки библиотек при проверке не требуются.

## Модель и начальные данные

- Условная геоцентрическая ECI: ось Z совпадает с осью вращения Земли, гринвичский угол равен 0 на эпохе `2026-09-28T00:00:00Z`. Вращающийся сферический наблюдатель: широта 25,3026°, долгота 51,5132°.
- Константы согласованы со сценарием проекта: `R_E=6371 км`, `μ=398600,4 км³/с²`, `J₂=0,00108262668`, `Ω_E=7,292115·10⁻⁵ рад/с`. Начальные элементы каждого КА — **оскулирующие** классические `(a,e,i,Ω,ω,ν)` на этой эпохе. Прямое преобразование в `(r,v)` выполняется двухтельной формулой для мгновенного оскулирующего конического сечения; затем интегрируется полное ускорение J₂, без осреднения и манёвров.
- Опорная круговая орбита на начальном обзоре имеет высоту 500, 600, 630 или 700 км; перебираются внешние угловые стороны 2°, 5°, 10°, 20°. Дополнительно испытываются множители начальных относительных скоростей, дальностей, фаза ±60 с и наклонение 60° наряду с 97,8°. Исходное семейство относительных состояний построено от прежнего четырёхточечного кандидата. **Только начальные данные** внутренних точек интерполируются по углам; затем каждый КА распространяется независимо. Это ограниченное семейство и детерминированный обзор, а не глобальная оптимизация.
- Методический источник для выбора высот и вопросов повторения трассы: А. А. Чернов, Г. М. Чернявский, [«Орбиты спутников дистанционного зондирования Земли», гл. 4–5, 8](https://djvu.online/file/G7PX23xQ2clNg) (2004). Кратность трассы одного КА служит только подсказкой для кандидатов. Приемлемость **всей сетки** при каждом следующем пролёте пересчитывается из абсолютных траекторий.

## Условия приёмки

В каждом узле всех КА требуется определённая гномоническая проекция и угол места не ниже 15°. Четыре угла, в порядке 0–1–2–3 для N=2, проверяются по существующим допускам: относительная ошибка сторон ≤0,1, диагоналей ≤0,1, углов ≤10° и выпуклость. При N>2 дополнительно проверяются точки регулярной сетки (максимальное отклонение ≤0,1 соседнего шага после подбора общего поворота и масштаба), равномерность соседних шагов ≤0,1, те же допуски сторон/диагоналей/углов каждой ячейки, выпуклость ячеек и порядок всех строк и столбцов. Минимальный **истинный** угол между соседними лучами рассматривается отдельно для 1° и 2°; он не заменяет внешний размер.

Для каждого непрерывного набора принятых 5-секундных узлов сохраняются границы, длительность и минимальная/максимальная внешняя сторона `atan(средняя гномоническая сторона)`. Это численный минимум на проверенных узлах, а не аналитическая гарантия на бесконечном множестве моментов. По числу таких пролётов за проверенный горизонт и разностям их средних времён оценивается повторяемость. Возможные более короткие эпизоды между 5-секундными узлами остаются ограничением метода.

Для всех `S(S−1)/2` пар на всём **фактически выполненном** горизонте вычисляются относительные положения через 60 с при шаге RK4 не больше 10 с. Внутренние минимумы уточняются по кубическому полиному Эрмита положения и скорости, а близкие к порогу — повторным интегрированием пары с шагом не больше 0,1 с. Глобальный минимум дополнительно уточняется J₂-интегрированием. Указываются UTC, время от эпохи и геоцентрическое место середины пары. Геометрическая сумма радиусов КА принята **условно** равной 0,02 км; запас 1,0 км задан отдельно. Реальные габариты, неопределённость орбит, атмосферное торможение и другие возмущения неизвестны, поэтому даже выполнение этих порогов не означает безусловную безопасность. Шаговая проверка с поиском экстремумов не является строгим доказательством отсутствия очень короткого неразрешённого события.

Отдельный диагностический предел высоты каждого КА — 300 км. Ниже него результат 30-суточной модели J₂ без атмосферного сопротивления помечается как неприменимый для физического вывода. Это условный предел модели, а не нормативная граница безопасности.

## Вычислительный бюджет и файлы

Базовый горизонт — **30 суток после эпохи**, плюс 450 с до неё для полного первого пролёта. В сохранённом расчёте он полностью выполнен для N=2, 3, 4 и 6; для N=5 и N=7…10 подробный аудит ограничен **одними сутками** после эпохи, также с добавленными 450 с до неё. Это обозначено в каждом решении полем `verified_30_days=false`; долгосрочный вывод для них не делается. При любом N алгоритм запускается, но 30-суточный аудит 4950 пар при N=10 требует значительно больше времени. Флаг `--full` позволяет выполнить его без изменения кода.

- [survey.json](results/survey.json) — все допустимые пробные наборы, короткое окно и причины отбраковки начальных состояний.
- [solutions.json](results/solutions.json) — по одному **проверенному на указанном горизонте кандидату** для каждого N, все элементы КА, строки сетки, найденные пролёты, нарушения и ближайшая пара. Поле `mission_recommendation=false` запрещает трактовать любой из них как готовую миссию.
- [summary.csv](results/summary.csv) — по отдельной строке для порогов 1° и 2°; столбец `horizon_days` обязателен для интерпретации.
- [minimum_convergence.json](results/minimum_convergence.json) — контрольные минимумы N=8 и N=9 при узлах 30 с и шаге интегрирования 5 с.
- [polar_controls.json](results/polar_controls.json) — отдельное однодневное сравнение N=9 и N=10 при наклонении 97,8°; его элементы и минимумы всех пар сохранены отдельно от выбранных кандидатов.
- `grid_n*_pair_minima.csv` — минимумы всех пар соответствующего N, `grid_n*_passes.png` — **отдельный** график повторных пролётов, `grid_n*_first_pass.png` — размер, истинный шаг, видимость и допустимые узлы первого пролёта конкретного рассчитанного случая.

Параметры `survey_candidate_budget_per_size` и `detailed_horizon_budget_days_by_size` позволяют увеличить обзор и время проверки. Граница обзора 20° взята из текущей демонстрации; отсутствие решения внутри неё не доказывает невозможность вне неё. Отбор по произведению длительности и минимальной стороны выполняется по первому дешёвому пролёту; подробная проверка может отвергнуть выбранный набор. Недоминируемые **только по первому пролёту** наборы сохранены отдельно, поэтому их нельзя считать 30-суточным фронтом Парето.
