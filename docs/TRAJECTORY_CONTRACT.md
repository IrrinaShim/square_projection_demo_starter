# Единый результат расчёта для графической оболочки

Графический модуль получает подготовленный объект `TrajectoryResult` от расчётного модуля. Он не интегрирует уравнения движения, не вычисляет проекцию и не импортирует исходный проект CasADi. Смена расчётной модели должна затрагивать только провайдер и, при необходимости, его адаптер.

## Обязательные поля

Пусть `M` — число отсчётов, `S` — число аппаратов. В режиме независимых орбит `S=N²`, где `N=2…10` — число КА на стороне сетки; в историческом и HCW-режимах `S=4`. Индекс 0 всегда относится к опорному КА. Массивы сохраняют одинаковый порядок аппаратов и строго возрастающее время. Индексная матрица `grid_indices` хранится в метаданных; при `N=2` она равна `[[0,1],[3,2]]`.

| Поле | Размерность | Единицы и смысл |
| --- | --- | --- |
| `t_s` | `(M,)` | Секунды относительно выбранной эпохи сценария. |
| `r_eci_km` | `(M,S,3)` | Абсолютные радиус-векторы в одной геоцентрической инерциальной системе. |
| `rho_oso_km` | `(M,S,3)` | Относительные координаты в локальных осях ОСО. Для данных исследования начало — геометрический центр всех КА, `mean(rho,axis=1)=0`; для сохранённых сравнительных провайдеров начало — КА 0, `rho[:,0,:]=0`. Конвенция находится в `metadata.local_frame_origin`. |
| `observer_eci_km` | `(M,3)` | Положение наблюдателя в той же инерциальной системе. |
| `image_gnomonic` | `(M,S,2)` | Безразмерные координаты `(xi, eta)` гномонической проекции; `p_0=(0,0)`. |
| `image_valid` | `(M,S)` | Булево значение: направление попадает в положительную полусферу проекции и численно определено. |
| `elevation_deg` | `(M,S)` | Угол места над местным горизонтом. |
| `accel_oso_m_s2` | `(M-1,S,3)` | Фактически приложенное ускорение на полуинтервале `[t[k],t[k+1])`. |
| `dv_cumulative_m_s` | `(M,S)` | Накопленная характеристическая скорость; значение в первом узле равно нулю для показываемого участка. |
| `shape_errors` | `(M,3)` | `epsilon_b`, `epsilon_d` и `epsilon_gamma` внешнего квадрата из TeX; последняя величина в радианах. Для `N>2` метрики внутренних точек и ячеек находятся в `metadata.grid_metrics`. |
| `min_pair_distance_km` | `(M,)` | Минимум расстояния по всем различным парам КА на показываемом пролёте. Отдельный уточнённый аудит текущей модели J₂ с сопротивлением охватывает показываемое окно и полный виток каждого сохранённого случая N=2,3,10; результаты находятся в `orbit_study/drag_demo/results/`. Многосуточный горизонт для неё не проверен. |
| `target_image_gnomonic` | `(S,2)` | Целевые точки на общей эпохе. |
| `reference_orbit_eci_km` | `(K,3)` | Дополнительная линия опорной орбиты для 3D-вида; `K` не обязано равняться числу узлов пролёта. |
| `metadata` | структура | Имя модели, источник данных, сценарий, единицы, конвенция угла, предупреждения и горизонт проверки безопасности. |

Допустимые дополнительные поля: `impulses` с временем, индексом КА и вектором `delta_v_m_s`; `required_accel_oso_m_s2` для расчётного ускорения, которое **понадобилось бы** для точной заданной картинки. Эти поля нельзя смешивать с фактически приложенным ускорением.

Контракт может быть реализован как проверяемый `dataclass` с массивами NumPy. Экспорт в файл полезен, но для первой версии достаточно объекта в памяти и возможности загрузить старые CSV через адаптер. Валидатор должен сообщать об ошибках размерности, неупорядоченном времени и несогласованных единицах. В `image_gnomonic` допускается `NaN` только там, где `image_valid=false`; связанные показатели формы тоже могут быть `NaN` в такой момент. Интерфейс пропускает эти точки и показывает причину. Бесконечные величины и `NaN` в остальных обязательных полях являются ошибкой данных.

## Геометрия и единицы

В сценарии свободного движения `angular_side_deg=theta` означает угол между лучом на опорный КА и лучом на ближайшую вершину вдоль одной оси картинной плоскости. Для расчёта `alpha=tan(theta*pi/180)`, затем целевые точки в порядке обхода:

`p0=(0,0), p1=(alpha,0), p2=(alpha,alpha), p3=(0,alpha)`.

Гномонические координаты безразмерны. Для подписей осей графика можно использовать `atan(xi)*180/pi` и `atan(eta)*180/pi`; подписи должны объяснять, что это координатные углы, а не одинаковое истинное угловое расстояние между каждой парой соседей. Геометрические критерии из TeX считаются по исходным `xi,eta`.

При базовой высоте 630 км и `x_i(t0)=0` начальная поперечная сторона равна `L=630*tan(theta)` км. Прежним 20 км соответствует `theta=atan(20/630)=1.8183029644518331` градуса. Значение 20 градусов означает поперечную сторону около 229 км; визуализация разрешена, а физическая достоверность линейной динамики должна быть явно помечена как не проверенная.

Графиков тяги в действующем окне нет. `accel_oso_m_s2` и `dv_cumulative_m_s` сохраняются в контракте для различения фактически приложенного управления и расчётного требуемого ускорения. Для пассивных независимых орбит с J₂ и сопротивлением они равны нулю: гравитация и сопротивление не являются приложенной тягой. Накопленное `Delta v` для постоянного на полуинтервале приложенного ускорения увеличивается на `norm(a_i[k])*(t[k+1]-t[k])`.

При `N>2` графики показывают все точки сетки и линии её строк и столбцов; подписи ограничены четырьмя углами. Критерии внешнего квадрата используют угловые индексы, а критерии всей сетки и аудит расстояний используют все `S` аппаратов.

В режиме исследования `metadata.center_eci_km` и
`metadata.center_velocity_eci_km_s` содержат средние абсолютные положение
и скорость всех КА; `metadata.local_velocity_oso_km_s` — скорости
относительно центра с учётом вращения локальных осей. Оси определяются
мгновенными `r₀,v₀`, однако центр не становится дополнительным КА.
Проекция `image_gnomonic` всегда рассчитывается из `r_eci_km` и
`observer_eci_km` и не зависит от выбора локального начала.
